## Workflow（每类代码必须走完四步）

```
① 代码阅读  →  ② 文档编写  →  ③ 内容扩充  →  ④ 质量验收
                  ↑                            │
                  └──────── 不合格打回 ─────────┘
```

- **① 代码阅读**：逐文件读源码，记录函数/变量/常量/数据流。
- **② 文档编写**：按统一模板产出初稿。
- **③ 内容扩充**：把每个函数展开到「签名 + 作用 + 实现要点 + 调用关系」，附代码片段与 `文件:行号`。
- **④ 质量验收**：按下方标准逐项打分，不合格打回 ①~③ 重做。

## 质量验收标准

| 维度 | 合格线 |
|------|--------|
| **文件覆盖** | 模块内每个 `.c/.S/.h/.v/.mk/.ld` 都有独立小节 |
| **函数覆盖** | 每个函数都有：签名 + 作用 + 实现要点 + 调用者/被调用者 |
| **变量覆盖** | 每个全局/静态变量/关键寄存器/常量都有说明（值、含义、读写方） |
| **准确性** | 所有 `文件:行号` 引用、常量值、地址、偏移量经 grep/read 核对，无错误标注 |
| **深度** | 关键逻辑（译码、地址换算、状态机、偏移计算）附代码片段并解释「为什么」 |
| **bug 攻击面** | 末尾有「症状 → 根因 → 定位路径」表，覆盖该模块可注入点 |

**打回条件**（任一命中即不合格）：
1. 某函数只一行带过，无实现要点；
2. 行号/常量/地址标注与源码不符；
3. 缺 bug 攻击面小节；
4. 关键地址换算/状态机逻辑未解释清楚。

## 文档统一模板

```
# 标题
## 1. 模块职责（一句话 + 它在整体中的位置）
## 2. 文件清单（表格：文件 | 作用）
## 3. 逐函数/逐变量详解（核心，占 60%+ 篇幅）
## 4. 执行流程 / 数据流（时序）
## 5. bug 敏感点（症状 → 根因 → 定位路径）
```
